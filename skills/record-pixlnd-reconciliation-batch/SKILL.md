## When to Use
Recording explicitly approved ontology decisions, not implementing gameplay. First read docs/lessons.md, the current HANDOFF and any pending queue. Compaction or a completion notification never authorizes another reconciliation: if the current objective is handoff/review, finish only the existing work's review, verification record and previously authorized commit/push, then stop.
## Recording routes
For source precision, explicitly load sibling `../record-finding/SKILL.md`; for significant choices, explicitly load sibling `../record-impactful-decision/SKILL.md`. New substantive source history has one home at `docs/findings/<slug>.md`; only major meaningful choices qualify for `ontology/decisions/<slug>.md`. Effective rules stay in ontology. Routine approvals/refusals, reviews and commit/run receipts stay in managed evidence. §E (`docs/ROADMAP/todo_decide.md`), §7 and README/status references, including unchanged Handoff steps/verifications, mean concise indexes/links/current pending state, not narrative archives. Unmigrated historical records remain valid read-only references: no migration, reapproval or deletion. Preserve exact amendments, HOLDs and pending application; resolve real domain anchors, never ontology/domain/index.md §E.

## Procedure
1. Check actual branch/worktree; capture exact owner answers and authority in a scratch brief. A request to commit several times partitions only the authorized diff, not additional implementation or push. Preserve unrelated edits/index state. Before canonical recording, save every unhandled selection/amendment, original proposal, dependencies and approval/application status in docs/todo_handle_reconciled_items.md; this pending-only queue is not a second ontology.
2. Check combined selections against current canonical rules and real instance shapes. Resume Previously selected entries without unchanged reapproval; clarify only real conflicts while preserving independently approved principles. Standing sourcing-only approval covers defensible attribution refinements, never gameplay, labels or stronger certainty than the evidence. Preserve contradictory reports and edition uncertainty without choosing historical truth or reopening settled mechanics.
3. Keep one writer per worktree. Where the owner requires a separate fresh subagent per item, launch distinct serial writers, not one batch writer. Each cold-start task needs exact managed evidence/artifact references, public-source boundaries and exact review-instruction paths; do not rely on another task's 'above' context or rediscover them with broad /tmp/home scans. Require explicit recording authority and exclusive worktree ownership. For authorized effective-rule changes, canonical ontology first, then the loaded decision helper only for significant choices. Source deltas use the loaded finding helper without rule changes. README, ledger/status/deferral and queue updates are concise links/current pending state; no gameplay/live-data/checker work follows from documentation approval.
4. For each substantive item inspect semantic/scope/source fidelity, run simplify then ponytail-review, apply justified reductions, run git diff --check and bounded ontology validation, then create one scoped conventional commit. Retain raw logs/exits and matching git diff --binary --full-index unstaged/staged/committed evidence. Keep the selection queued until required review and commit are verified; then retain major-choice authority/amendments in its decision record and sourcing authority plus review/hash receipts in managed evidence, with only concise record/evidence pointers in §E, and remove its entry, deleting an empty queue. Routine receipts alone create no knowledge record or invented commit. Setup/tooling failures require retained evidence and supervisor-authorized same-protocol continuation, not guessed success or mode switching.
5. When late approvals arrive, update the binding brief and queue, notify the same writer, then inspect actual output/commits for coverage. A queued steering receipt does not prove compliance.
6. Fresh-review the substantial batch against saved public sources/current files/diffs/logs. Parent inspects actual Git scope and byte correspondence, reruns bounded validator/boot, resolves valid findings and finalizes truthful receipts. Preserve invariants while permitting explicitly inspected status-only changes in preservation audits; retain initial failed assertions. Before resuming a reviewer, archive its earlier output in managed evidence and keep only its pointer in the ledger: resumed managed output can overwrite the same path. Keep recording review, follow-up closure review and parent command evidence distinct. Inspect current-status wording in the implementation ledger even when no implementation debt changed.
7. Follow ontology-reconcile-topic's context reserve: question presentation by ~60%; handoff begins by ~85% or earlier. If percentage is unavailable, use bounded batches and checkpoint conservatively without inventing a percentage or imposing an automatic one-item stop. Follow its pending-only Handoff contract: remove handled points once progression and unique facts are visible in existing project records; a complete/terminated project has an empty handoff. Defer HANDOFF writes while another agent owns it. Preserve unhandled approvals, remove handled queue entries, commit authorized verified checkpoint/queue changes, and push only with current authorization. After an authorized normal push verify fresh remote/upstream/local equality and clean state, then STOP. Without push authority record a local checkpoint, not publication.
## Pitfalls
- Documentation approval never authorizes runtime, loader, validator, tests or behavior-changing JSON.
- A green Godot validator cannot prove natural-language consistency or implementation of documented policies.
- Do not call a topic finished while concrete player-visible cases remain unanswered; do not expand into speculative new features.
- Old commit hashes after a rebase are historical evidence, not current identities or fresh test proof.
- An explicit owner exception takes precedence over a later general instruction to preserve existing assignments. Record coherent approvals separately from conditional subcases, without letting the unresolved subcase undo the approved exception.
- For temperament/tameability amendments, inspect pet-food.json rules as well as species traits. If the owner specifies ordinary base-type behavior, reuse those rules rather than inventing variant-only passivity or provocation exemptions. Tameability alone does not choose bait or riding.
- When a shared-food exception is approved, reconcile relation cardinality and the source-ID constraint together. Preserve the existing food subtype and each species' source identity; do not assign the food's source ID to the added species or invent its missing ID. Direct data correction and model/loader/validator changes remain separately authorized.
- Pixlnd is undeployed and has no existing player data to migrate. Require current approved rules directly; replacing stale checked-in definitions does not call for migrators, legacy-read fallbacks or compatibility paths. Distinguish a precise approved definition from stale data and missing enforcement rather than reopening the mechanic.
- Validate scout inventories against actual source shapes before recording them. In creature-families.json, landscape-rosters has creature-ID arrays, whereas forest-dungeon-rosters has objects with members arrays and boss strings that include race/family tokens; a similarly named table does not inherit another table's validation contract.
- Before the final handoff commit, replace temporary writer status such as 'uncommitted' or 'review pending' with actual review/verification evidence. Label recorded Git refs as pre-publication checkpoints; verify remote HEAD and clean worktree after the authorized push rather than claiming publication in advance.
- When the authorized parent objective is handoff/review, resume or compaction notices continue that objective, not the next reconciliation topic. If the owner assigns reconciliation to a new agent, finalize/review the handoff and stop. Preserve any unpresented source candidates as unapproved leads; draft scratch labels are not reserved item numbers or owner ballots.
## Verification
1. Each substantive resolved item has its own commit and concise index pointer, unless the owner explicitly withholds commit authority. Verify loaded-helper routing and significance, one finding/major-decision history home, preserved uncertainty/contradictions and unchanged legacy blocks; routine receipts remain managed evidence.
2. Only authorized files changed; current summaries distinguish approved policy from deferred runtime.
3. The validator exits successfully and logs show ontology valid; source/semantic review establishes fidelity separately.
4. Compare saved per-item and final handoff diffs with actual staged/committed Git diffs using matching explicit options: git diff --binary --full-index. Preserve an initial failed comparison and rerun with matching formatting rather than normalizing differences away.
5. If unfinished continuation exists, HANDOFF names its next action or references its exact questions/queue; a complete/terminated project with no continuation needs has a zero-byte HANDOFF. Publication matches owner authorization. After authorized pushing, verify local HEAD, fresh remote branch SHA and upstream agree, and git status --porcelain is empty.
6. When an approved exception already matches runtime, source-trace availability, state ownership and consumers and run relevant existing bounded regressions. Record only actual enforcement/metadata gaps as debt; do not invent implementation work solely because a matching behavior was newly approved. Distinguish regression coverage from comprehensive proof.
7. For an authorized new pending-queue commit, stage only its authorized path, verify staged scope and run git diff --cached --check. A git diff --no-index --check exit 1 with empty diagnostics may merely indicate different files; preserve that result and follow the governed recovery protocol. Keep the queue intact if unstaging is required.
8. Check newly introduced decision/application dates against the actual current clock/request evidence. Preserve historical approval/source/capture dates; distinguish current application from the origin of older standing approval.
9. When the owner authorizes recording but withholds commits, keep approved worktree-recorded selections queued through checks and independent/parent review; only commit closure remains pending. Set HANDOFF to WAIT, remove stale review-pending wording after review, and make no staged/committed/published claim. Do not let ordinary per-item or handoff commit/push instructions override the explicit hold.
10. Compare saved index inventories with identical git ls-files --stage options and record delimiters. LF output and --stage -z output differ even with identical entries. Preserve a failed assertion, diagnose exact bytes/flags, then compare matching raw outputs without normalizing the baseline.
